# 侧栏文字导航与阅读位置记忆设计

日期：2026-09-12  
状态：已获用户确认，待实施

## 目标

1. 将桌面端现有 64px 纯图标左侧导航扩展为约 158px 的“图标＋文字”导航，让“人物、关系、大纲、事件、章节、设定、便签、用量、智能体”等入口更醒目。
2. 提供还原按钮，将侧栏恢复为当前版本的纯图标状态；用户选择的侧栏状态永久保存在本机。
3. 记忆章节、大纲、人物等页面的左侧列表和右侧正文/详情滚动位置。位置按工作区和页面隔离，重新进入时恢复，不再每次从顶部开始翻。

## 交互设计

### 侧栏

- 首次使用默认采用展开态，宽度约 158px；宽度只为容纳中文导航文字，不增加第二层内容面板。
- 展开态每个入口显示图标和文字，当前入口使用现有 accent 高亮；品牌标识保留在导航顶部。
- 侧栏底部增加“还原图标”按钮。点击后进入纯图标态，入口继续保留悬停文字提示；纯图标态提供同一位置的展开按钮。
- 侧栏展开/折叠状态写入本机持久化存储，刷新、重启应用后保持。该偏好不写入项目目录，也不影响其他用户或其他设备。
- 移动端继续使用底部导航，不把 158px 桌面侧栏强行应用到窄屏；如果移动端存在可展开导航，复用同一状态语义但遵守底部导航布局。

### 阅读位置

- 为每个需要长列表或长内容的页面绑定可识别的滚动容器：
  - 章节：章节列表和正文编辑/阅读容器；正文箱、草稿箱、回收站分别隔离。
  - 大纲：大纲列表和右侧详情/正文容器。
  - 人物：人物列表和人物详情容器。
  - 其他同样采用双栏阅读的页面可复用同一机制，不改变其业务数据。
- 位置键至少包含工作区唯一标识和页面标识；有页面子区域时再包含子区域标识，例如 `chapters:main`、`chapters:draft`。
- 进入页面或切换子区域时，在内容完成挂载后恢复对应位置；没有记录时保持默认顶部位置。
- 监听滚动时使用防抖写入，避免每个滚动事件同步写存储；页面卸载或切换前再补写一次最新位置。
- 位置恢复只影响滚动条，不覆盖用户当前选择、编辑草稿、搜索词或未保存内容。恢复失败或存储不可用时静默回退到顶部，不阻塞页面。
- 记录使用有限、可序列化的数据（scrollTop/scrollLeft），必要时清理未知或过期的异常值；不保存正文内容和项目数据。

## 技术方案

- 在 renderer 共享层新增小型阅读位置存储/Hook，负责键生成、读取、限幅、保存和恢复时机；页面只传入 scope、workspaceId 和滚动容器 ref。
- 侧栏状态使用独立的 renderer 偏好键，避免混入服务端 `PublicAppSettings` 或项目文件格式；阅读位置使用带版本号的独立存储键，方便未来升级。
- workspace 标识优先使用当前工作区稳定路径/ID，不使用名称，防止重名项目串位。关闭工作区时不删除记录，以满足重新打开仍能回到上次位置。
- 对不存在的 DOM 容器、SSR/移动端不可用的 `window` 或非法存储数据，使用安全空实现；不让持久化异常影响导航和正文加载。

## 验收标准

- 桌面端展开侧栏后能看到所有导航文字，宽度约 158px，主内容区没有明显不必要的挤压。
- 点击还原后恢复当前纯图标外观，刷新和重启后仍保持用户最后一次侧栏选择。
- 在工作区 A 的章节列表、章节正文、大纲列表、大纲详情、人物列表、人物详情分别滚动后离开，再返回均恢复到各自位置。
- 切换到工作区 B 后使用相同页面不会显示工作区 A 的滚动位置；回到 A 后仍可恢复 A 的记录。
- 章节切换正文箱/草稿箱/回收站时位置不串用；搜索、编辑和未保存草稿行为不受影响。
- 320/360/768/1280 CSS 像素宽度下无横向溢出；移动端仍是底部导航布局。
- 单元测试覆盖键隔离、状态读写、非法值回退、防抖保存和多区域位置恢复；构建验证覆盖 Electron、Web、移动端。

## 非目标

- 不在侧栏增加章节、大纲、人物的第二层树状内容面板。
- 不把阅读位置同步到服务器、项目 ZIP 或 `docs` 文件夹。
- 不改变项目实体的排序、选择、编辑保存和导航路由语义。
