# StoryFabric 开源生态页与版本描述展示设计

日期：2026-09-14

## 背景

`StoryFabric-web` 是一组不依赖构建工具的静态产品介绍页，当前包含首页、写作台、故事世界、智能体和下载页。用户希望把已经开源的 StoryFabric 项目单独介绍出来，让访问者理解项目定位，并能分别获得“分享项目”和“参与拓展”的入口。

项目公开仓库为 [github.com/lefengyao/StoryFabric](https://github.com/lefengyao/StoryFabric)。仓库 README 将 StoryFabric 定位为面向智能体的小说创作与工作区管理工作台，包含章节、故事资料、模型接入、工具确认、导入导出等能力；代码按 `src/core`、`src/main`、`src/preload`、`src/renderer`、`src/server` 和 `examples` 等区域组织。本页只引用稳定的项目定位与参与方式，不把会变化的 star、release 或版本数量写死在页面中。

另外，下载页已经支持从版本清单读取最新发布信息，但当前“最新正式版”卡片没有把清单中的 `description` 渲染出来。因此发布者即使在上传向导中填写了“发布描述”，普通访问者也看不到这段说明。

## 目标

1. 新增独立的“开源”页面，清晰说明 StoryFabric 是什么，以及为什么欢迎用户分享和拓展。
2. 让“分享者”和“拓展者”两类访问者都能快速找到符合自身角色的行动入口。
3. 复用现有暖纸张、深蓝墨色、珊瑚强调色和工作台卡片视觉，不引入新的构建工具或外部依赖。
4. 将最新版本的发布描述显示在下载页正式版卡片中，使上传向导填写的内容真正对外可见。
5. 保持无版本数据时的“敬请期待”空状态，不因新增版本描述逻辑恢复任何硬编码下载按钮。

## 非目标

- 不在静态站内接入 GitHub API、登录、Issue 创建或在线编辑功能。
- 不修改 StoryFabric 内层 Electron、Node 服务或数据结构。
- 不承诺未发布的平台、自动同步、在线协作或固定发布时间。
- 不把 Markdown 当作 HTML 注入下载页；版本描述按纯文本安全展示。
- 不重新设计已有产品页，只做导航接入和与新页必要的样式复用。

## 页面结构

新增 `StoryFabric-web/opensource.html`，页面使用与现有页面一致的导航、页脚和 `data-page="opensource"` 标识。导航顺序调整为：产品、写作台、故事世界、智能体、开源、下载；五个已有页面和新页面都要同步更新，且开源项在当前页有 active 状态。

### 1. 首屏：把写作工具，交还给故事的人

- 以“StoryFabric 已经开源”为核心信息，而不是把页面写成下载页的重复版本。
- 简短解释：这是一个把小说资料、章节结构和可控智能体放在同一张工作台上的项目。
- 主按钮跳转到 GitHub 仓库，并使用新窗口打开；按钮文字明确为“查看 GitHub 仓库”。
- 次级入口跳转到现有产品页或下载页，帮助首次访问者先了解产品。
- 视觉上沿用产品总览卡片，可放置章节、故事资料、智能体确认写回三个简洁状态块，避免制造一个与真实应用不一致的伪功能界面。

### 2. 双入口：给分享者的话 / 给拓展者的话

使用左右并列、移动端纵向排列的两张主卡，文案保持均衡：

- **给分享者的话**：欢迎转发项目主页、GitHub 仓库和真实使用体验；分享时尽量说明适用场景、当前平台状态和自己的工作流，帮助更多创作者判断它是否适合自己。
  - 入口：查看仓库、了解产品。
  - 边界：不暗示已有完整生态、稳定发行版或所有平台均已成熟。
- **给拓展者的话**：欢迎从文档、示例、界面、模型适配、服务端和问题反馈等小切口开始；先理解工作区、资料读取和确认写回的边界，再提交可复现、可讨论的改进。
  - 入口：查看源码结构、阅读贡献说明/提交 Issue。
  - 边界：页面不虚构尚未存在的贡献指南文件；若仓库没有独立贡献文档，统一引导至 GitHub 的 README、Issues 和源码目录。

### 3. 项目形状

用轻量流程/目录卡片说明参与者可以从哪里开始：

`故事工作区` → `章节与资料` → `智能体读取` → `用户确认写回`

旁边补充源码入口：核心逻辑、桌面主进程、渲染界面、服务端和示例。这里只做导航性解释，不展示会随仓库变动而失真的具体文件数量或 API 数量。

### 4. 结尾 CTA

用一句邀请收束：“如果你正在写故事，欢迎先试用；如果你正在做工具，欢迎从一个具体问题开始。”

提供两个按钮：返回产品介绍、前往 GitHub。所有外部链接加 `target="_blank"` 和 `rel="noreferrer"`。

## 版本描述显示

### 数据来源

不改变现有版本清单优先级：运行时优先读取 `downloads/versions.json`，失败时使用 `assets/versions.js` 的空回退清单。页面继续由清单决定是否显示正式版本；没有 releases 时仍显示“敬请期待”。

### 展示规则

- 在下载页 `renderLatestRelease()` 的正式版卡片中，在版本号/发布日期附近增加发布描述区域。
- 当 `latest.description` 是非空字符串时显示其纯文本内容；为空、缺失或只有空白时不显示空的描述框。
- 使用 `createElement` 与 `textContent`（或等价的纯文本节点）写入，不能把发布描述拼接进 `innerHTML`，避免上传者输入的 HTML 被执行。
- 历史版本列表继续显示各自的 `release.description`；保持现有空描述兼容逻辑。
- 上传向导中的 `发布描述` 字段保持原有提交字段名 `description`，不额外强制必填；这样发布者可以选择只填版本号和安装包。

## 视觉与交互

- 复用 `assets/styles.css` 中现有的导航、按钮、section、卡片、标签、响应式网格和 hover 状态。
- 新页使用一个具有开源语义的视觉标记（如代码分支/连接节点/仓库图标），优先使用现有图标系统或内联 SVG，不新增图标依赖。
- 两张受众卡在桌面端保持同等视觉权重，颜色只用于区分“传播”和“参与”，不让任一角色成为次要入口。
- 外部链接具备清晰的 focus 状态；按钮和链接文本在窄屏下不被截断。
- 保持现有轻量进入动画；若用户设置减少动态效果，页面内容仍完整可用。

## 技术方案

- 只新增 `StoryFabric-web/opensource.html`，并修改已有 HTML 的导航、共享 CSS、必要的共享 JS 和下载页 QA 用例。
- 不新增 npm 依赖，不引入框架，不改变静态服务器路由。
- 复用 `assets/app.js` 的当前页导航激活逻辑；若当前逻辑是按页面标识匹配，则只补充 `opensource` 的导航项。
- 版本描述使用一个小型渲染辅助函数或在 `renderLatestRelease()` 内完成，避免扩大全局状态范围。
- 新页所有产品事实与链接集中在 HTML 文案中，暂不增加额外 JSON 配置；未来若仓库地址变化，只需修改单页中的链接。

## 验证标准

### 静态检查

- `opensource.html` 存在，标题、导航、GitHub 链接和两类受众文案齐全。
- 六个页面的导航都能互相跳转，当前页 active 状态正确。
- GitHub 外链地址准确为 `https://github.com/lefengyao/StoryFabric`，外链具备新窗口和安全 rel 属性。
- 下载页不再包含无版本状态下的硬编码安装包按钮。

### 行为检查

- 使用合法版本清单时，最新正式版卡片显示版本号、日期、安装入口和发布描述。
- 发布描述包含 `<script>` 或 HTML 字符串时，页面只显示文字，不创建可执行节点。
- 发布描述为空时，正式版卡片不出现空白描述容器。
- 使用空回退清单时，下载页仍显示“敬请期待”，且没有下载按钮。
- 桌面和窄屏视口下，新页双卡片、CTA 和导航均不发生明显溢出。

### 工具验证

- 运行现有 `.qa/download-page.test.cjs` 及新增/更新的开源页静态断言。
- 对 `StoryFabric-web/assets/app.js` 执行 Node 语法检查。
- 通过本地静态服务器访问新页和下载页，检查控制台无新增错误。

## 风险与取舍

- GitHub README 的平台状态和目录结构可能变化，因此页面使用“当前仓库 README 所示”的稳定概括，不显示易过期的数字。
- “贡献说明”若仓库暂时没有独立文件，页面以 README、Issues 和源码目录作为起点，避免链接到不存在的路径。
- 纯文本显示会保留 Markdown 标记本身，但可防止发布描述破坏页面；后续若确实需要 Markdown，可单独引入白名单解析策略，不在本次范围内。
