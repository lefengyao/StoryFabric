# 便签任务完成后的删除询问设计

**日期：** 2026-09-08
**状态：** 已确认，待实现

## 目标

当用户在当前对话中明确完成一项与某条便签对应的任务时，智能体询问用户是否删除该便签。智能体不得自动删除；用户明确同意后，删除操作仍必须经过现有的待确认变更流程。

## 行为边界

触发条件必须同时满足：

1. 当前对话可以明确关联到某一条便签；
2. 用户明确表达任务已完成，例如“完成了”“已经处理好”；
3. 智能体已经通过 `list_notes` 或 `get_note` 确认便签内容和 `noteId`。

普通聊天中的“完成”、无法对应便签的任务、模糊表达或仅完成部分任务，都不触发删除询问。

## 交互流程

```text
用户完成便签任务
        ↓
智能体读取并确认关联便签
        ↓
询问“是否删除这条便签？”
   ┌────┴────┐
   │         │
拒绝/模糊   明确同意
   │         │
便签保留    调用 delete_note
                 ↓
          生成待确认变更
                 ↓
          用户确认后移入回收站
```

用户拒绝、暂不删除或没有明确同意时，不调用 `delete_note`。删除成功后的表述应为“已移入回收站”，不能声称永久删除。

## 工具与权限

新增 `delete_note` 智能体工具，参数为 `noteId`。工具执行逻辑复用现有 `deleteNote` 存储流程，将便签移动到回收站，并生成 `PendingChange`，实体类型为 `note`。

工具必须处理以下异常：

- `noteId` 缺失：返回明确参数错误；
- 便签不存在：返回未找到，不生成变更；
- 用户未明确同意：智能体不得调用工具；
- 用户拒绝待确认变更：便签保持原位置；
- 用户确认待确认变更：便签进入回收站，可通过现有恢复流程恢复。

不改变现有便签 Markdown 格式、UI 删除入口或回收站数据结构，不增加后台自动识别和自动删除。

## 提示词规则

规则放入共享核心系统提示词，桌面端复用同一份提示词。提示词明确：

- 便签是任务记录，不代表任务一定完成；
- 只有明确关联且用户明确表示完成时才询问；
- 询问本身不等于删除；
- 只有用户明确同意后才调用 `delete_note`；
- 工具返回 `pending` 不等于已经落盘。

## 测试与验证

新增测试覆盖：

- 明确完成且存在关联便签时触发删除询问规则；
- 无关联任务时不触发；
- 用户拒绝时不产生删除变更；
- 明确同意后生成便签删除待确认变更；
- 不存在的便签 id 安全失败；
- 确认后便签进入回收站；
- 核心与 Electron 主进程使用一致的提示词和工具定义。
