# StoryFabric 0.2.1：灵感台与智能体生成设计

**状态：** 已确认，待实施
**版本：** 0.2.1
**日期：** 2026-09-20

## 1. 目标与范围

0.2.1 在不改变既有章节、普通对话、Skill 或规则工作流的前提下，增加三个彼此独立的能力：

1. 在设置中提供一个全局的“智能体温度”创作控制。数值越高，输出越精准和稳定；数值越低，输出越发散，更利于探索创新。
2. 允许用户开启“正文提供多种方案”。开启时，完整正文默认生成三个候选，用户只能把明确选中的一个写入目标章节。
3. 增加“灵感台”。它只做命名、资料蒸馏和拆解，不拥有正文写入能力；蒸馏结果经用户确认后可发布为 Skill、规则集或项目文档。

本版本同时修复两个章节体验问题：智能体保存后字数未及时反映，以及正文箱中的编辑阶段被误读为“草稿箱”标签。

不在本版本范围内的是：自动从任意目录持续扫描资料、在没有用户操作时读取电脑文件、让灵感台自动写入章节、让拆解生成可安装产物、或先实现一套通用工作流引擎。未来 MCP 暴露应复用本次的核心服务，而不是由 MCP 重新实现业务逻辑。

## 2. 总体架构

采用独立的 `core/inspiration` 领域模块，而非将逻辑拼进现有正文智能体提示词或工具注册表。核心模块只依赖抽象的工作区文件、模型调用、时间和标识生成能力；Electron IPC、HTTP 服务和 Android 平台均作为适配层调用它。

```text
Renderer / IPC / HTTP / Android adapter
                  │
                  ▼
          InspirationService
  ┌───────────────┼────────────────┐
  ▼               ▼                ▼
SourceCatalog  AnalysisService  ArtifactPublisher
  │               │                │
Workspace FS  ModelCallGateway  Skill / Rule / Docs adapters
```

`SourceCatalog` 管理资料的发现、导入、来源与提取状态；`AnalysisService` 只生成结构化命名、蒸馏或拆解结果；`ArtifactPublisher` 只把用户选中的蒸馏片段转换为现有 Skill、规则或 docs 机制认可的候选。三者不直接引用聊天页面，也不注册 `save_chapter`。

公共契约放在 `shared/inspiration.ts`，包括 `InspirationSource`、`AnalysisRequest`、`AnalysisResult`、`PublicationCandidate` 和稳定的错误代码。未来 MCP 服务器只需把这些契约映射为资源和工具：列资料、导入、分析、预览发布、确认发布；它不能获得未在本地服务中存在的绕过式写权限。

## 3. 项目资料与数据边界

每个工作区新增一个可见的根目录 `inspiration/`，在界面中称为“灵感资料”。用户可手动把资料放入该目录及其子目录；灵感台扫描时发现它们，但不会改名、移动或删除。用户也可通过“从电脑导入”选择文件或手动提供路径：客户端必须先展示文件列表、大小和将发生的复制操作，得到确认后才复制到 `inspiration/imported/<source-id>/`。外部路径只作为一次性的导入来源，不会被后台持续读取。

元数据与提取缓存存放在 `.storyfabric/inspiration/`：来源 ID、相对路径、原始文件名、大小、导入时间、提取状态、内容摘要和分析历史索引。原始资料留在可见目录，缓存可被安全重建。工作区导入导出规则必须明确把 `inspiration/` 与 `.storyfabric/inspiration/` 纳入便携数据，并沿用归档的路径、数量、单文件、总大小和压缩包防护；资料二进制文件按独立的受限白名单处理，不再被“章节必须是 UTF-8”规则误判。

0.2.1 提供可插拔的 `SourceTextExtractor`。支持 UTF-8 `.txt` 和 `.md`，并为 `.docx`、`.pdf` 提供受限提取器；无法安全提取的格式保留为资料但明确标为“不可分析”，不伪造分析结果。每个来源、总导入量、提取文本量、单次分析上下文均设固定上限，并在界面显示。模型调用前明确告知用户：选中的提取文本将发送到当前所选模型供应商；用户可移除来源和缓存。

## 4. 灵感台产品与页面

新增顶级路由 `/inspiration` 与侧栏入口“灵感台”。视觉沿用现有“设定资料”的资料侧栏、“创作资源”的页签和“目标中心”的标题/状态层级：左侧为资料库和导入入口，右侧使用页签和居中内容列，不另起一套仪表盘视觉语言。

### 智能起名

输入命名对象、题材/时代、意象、禁用词和目标读者印象，返回若干可筛选的名称、释义、读音/辨识建议和适用风格。结果可复制或带回当前对话；不创建章节，也不显示发布为 Skill/规则/docs 的入口。

### 蒸馏小说

用户选择资料与分析目标，服务以分块归纳再总合的方式返回带来源引用的结构化报告：故事骨架、人物与关系、冲突、叙事视角、语言与句法、节奏、世界观、可复用约束，以及不确定/证据不足处。报告中的每个可发布片段由用户勾选，并显示三个明确动作：

- **保存为 Skill：** 转为现有内容包草稿，经内容包校验和用户确认后安装；不直接改写已安装 Skill。
- **保存为规则集：** 转为现有规则层候选，经规则校验、冲突提示和用户确认后保存。
- **保存到 docs：** 写入用户选择的单层 `.md` 或 `.txt` 项目文档；先做路径、大小和内容冲突检查，不能静默覆盖。

发布操作保存来源引用和生成时间。任何发布失败都不影响原报告，且不产生部分成功的跨类型写入。

### 拆解

复用资料选择、提取、引用和分析管线，但其结果只说明风格、结构、节奏、人物功能、场景组织和可借鉴/应避免的技巧。拆解页面没有 Skill、规则或 docs 发布控件，服务层同样拒绝这类命令。这一限制既是 UI 规则也是 API 规则。

## 5. 智能体温度与正文候选

在“设置 → 智能体”新增全局 `AgentGenerationPreferences`，不放入供应商的 `modelSettings`：

```ts
{
  agentTemperature: 70,       // 0–100；产品语义而非直接提供商值
  proseAlternativesEnabled: false
}
```

设置标题使用“智能体温度”，旁边固定说明“越高越精准稳定；越低越发散创新”，避免把本产品语义误解为模型供应商常见的相反定义。默认值 70（平衡）。核心解析函数将这个产品值集中映射为供应商调用参数，例如 `0 → 1.2`、`70 → 0.5`、`100 → 0.2`；模型或协议不支持温度时，保留偏好并在调用记录中标出未生效，绝不改写供应商的逐模型能力配置。

开启多方案后，完整正文请求进入独立的 `ProseCandidateService`。它把同一目标章节、当前修订版本、上下文和生成偏好交给三个独立候选调用，要求每个调用返回完整正文而不是提纲或片段。候选必须附带目标章节 ID、基线修订版本、字数、生成参数和短风格说明。候选在聊天中以三个可展开卡片展示；未选内容只存在于本次运行/会话，不写入章节、草稿箱、docs 或项目目录。

“选用并保存”是单独的用户动作，而不是模型工具调用。保存前服务重新核对章节 ID 和基线修订；若章节已被编辑，提示用户刷新或显式处理冲突，绝不覆盖。保存成功后通过既有受控章节写入路径提交，并立即发布包含新 `ChapterMeta` 的工作区变更事件。关闭开关时，保持当前单篇正文生成行为。本版本固定生成三篇候选，避免把简单开关扩展成额外的成本和数量配置。

## 6. 章节状态与字数修复

章节的 `box`（草稿/正文/回收箱位置）和 `status`（draft/revised/final 编辑阶段）继续保持独立；移动章节不应悄悄改变编辑阶段。问题在于 `status: draft` 的展示文字“草稿”与草稿箱混淆。

将编辑阶段的用户文案改为“初稿 / 已修订 / 定稿”，并把位置作为独立信息展示：在正文箱可显示“正文 · 初稿”，草稿箱则显示“草稿箱 · 初稿”或在页标题已明确位置时仅显示“初稿”。因此移入正文箱的章节不会再被显示为“草稿”，同时历史编辑阶段仍被保留。

章节存储目前会在保存时重新计算 `wordCount`；0.2.1 要修复的是从智能体写入到列表/编辑器可见态的刷新链路。核心写入结果必须携带最终 `ChapterMeta`（含字数和内容修订），桌面 IPC、HTTP 事件和 Android 平台无损转发。渲染端收到已应用的变更时，先原子更新工作区摘要中对应章节的元数据，再以带序号的刷新请求校验最终状态；较旧请求不得覆盖较新的保存。若当前打开且本地无未保存编辑，编辑器重载正文和字数；若本地有编辑，则保留草稿并显示外部更新冲突提示。

## 7. 错误处理与安全性

- 导入路径必须由用户在 UI 选择或明确输入；禁止智能体自行枚举磁盘、读取环境变量或跟随目录外的符号链接。
- 路径穿越、重复文件、无法读取、大小超限、格式不支持、编码失败、资料修改、模型取消和模型返回不符合结构化契约，均使用可展示的领域错误并保持现有资料/报告不变。
- 分析报告和发布候选分离。报告不能借由提示词或格式伪造绕过 Skill/规则/docs 的校验与确认。
- 资料内容只发送给用户当前选定的模型供应商；在发送前展示资料数量、预计文本量和隐私提示。
- 三候选生成途中取消时，不展示不完整候选；运行记录为已取消且不写章节。

## 8. 平台、版本与验证

共享契约和核心服务必须在桌面、HTTP 服务与 Android API 上保持同名/同语义的输入、错误码和变更事件。桌面可提供本机路径选择；无法访问本机路径的远程/Android 客户端只提供工作区资料上传，不伪装支持本机路径。MCP 是后续适配层，不在 0.2.1 提前引入服务器或认证方案。

必须新增或更新以下验证：

1. 生成偏好默认值、校验、持久化、跨适配层传递、温度映射和不支持温度的降级。
2. 三个完整候选、未选择不写入、选择后只写一个、章节修订冲突、取消和关闭开关回归。
3. 资料目录扫描、外部导入确认、格式/大小/路径安全、导入导出保留、提取错误和模型隐私提示。
4. 起名、蒸馏、拆解三个服务边界；蒸馏各发布器的校验/冲突/确认；拆解 API 和 UI 均拒绝发布。
5. 正文箱的“初稿”展示、移动不改变真实状态、智能体保存后列表和编辑器字数立即更新、乱序刷新不回退。
6. 现有章节写入、普通对话、Skill、规则、docs、归档、桌面 IPC、HTTP 和 Android 回归测试。

发布时将版本同时更新为 `0.2.1`，更新根 `package-lock.json`，运行 `npm run server:bundle` 与 `npm run dist:win`，并依据仓库发布规则验证独立服务器压缩包、嵌入桌面包、版本文件、安装器名和两个归档的 SHA-256 一致。已有工作区的无关未提交改动不纳入本次提交；本功能的源码、测试、设计和版本改动以明确路径单独暂存和审查。
