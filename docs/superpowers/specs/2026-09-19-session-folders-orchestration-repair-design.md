# 会话文件夹与编排运行修复设计

## 目标

将会话从单个 JSON 文件升级为“按日期和描述组织的会话文件夹”，让普通模式与编排模式成为可切换的会话级设置；同时修复编排阶段停住、工具保存失败、审批确认链路不稳定和版本号不一致问题。全部修复完成后，在指定小说项目中复制一份长期设定文档，按现行协作模式更新副本，不覆盖原文。

## 范围

本设计拆成四个可验收单元：

1. 会话文件夹、首次命名、临时文件和旧会话迁移。
2. 会话级普通/编排模式切换，以及归档、删除、恢复后的文件夹行为。
3. 编排工具权限、审批等待、写入版本和阶段失败恢复。
4. 复制并更新 `docs/修仙体系设计.md`，生成适配现行模式的副本。

不在本次范围内：重写七阶段编排模型、取消审批、把所有只读核对智能体改成可写智能体、修改原始小说文档内容。

## 现状与根因假设

- `CoreSessionStore` 和桌面 `SessionStore` 当前读写 `.storyfabric/sessions/<id>.json`。
- `ChatPage` 的 `normal/goal` 只控制 `RunAgentRequest.mode`；核心运行分支仍按会话快照中的 `creative.orchestrationEnabled` 决定是否编排。因此“普通模式”无法真正关闭编排。
- 写入工具先生成待应用变更；严格审批等待确认，其他策略直接尝试应用，但最终仍执行版本、参数和并发校验。
- `search_project` 的实体 `sourceRevision` 来自源文件文本，而部分 `save_*` 工具使用规范化实体序列化结果校验 `baseRevision`。这解释了指定项目中“重新读取仍失败、改用搜索结果版本号后成功”的版本口径异常，需要统一写入基线。
- 调度器在必要阶段失败后把后续阶段置为 `stale` 并结束运行，前端表现为运行停住；当前阶段记录已有失败信息，但恢复入口和审批等待状态还不够持久。

## 设计决策

### 1. 会话目录布局

```text
.storyfabric/
└─ sessions/
   ├─ 2026-09-19-优化第23章-sess_abc123/
   │  ├─ session.json
   │  └─ tmp/
   │     └─ run_xxx/
   └─ legacy/
      └─ sess_old.json

docs/
├─ 修仙体系设计.md
└─ 2026-09-19-修仙体系设计-编排适配副本.md
```

- 文件夹名称：`YYYY-MM-DD-安全简要描述-会话ID`。
- 文件夹内部的稳定主文件固定为 `session.json`，避免会话改名时移动正在运行的文件。
- `tmp/` 只存本会话临时资料、阶段中间结果、工具失败诊断和可恢复运行快照；不作为长期项目资料注入普通检索。
- 根目录 `docs/` 继续存放长期有效的项目文档；它不属于某个会话。
- 会话路径存储在会话记录的受控 `storageDir` 字段中，并通过路径安全校验只允许当前 `.storyfabric/sessions/` 下的安全目录名。

### 2. 首次命名

首次真正发送消息时执行一次轻量的会话命名请求：只允许输出短标题，不提供项目写入工具，输出长度限制在 24 个中文字符以内。成功后使用标题生成安全 slug，创建会话目录并保存 `session.json`；命名请求失败、超时或输出不合法时，回退到现有的 `titleFromMessage`，不能阻断主任务。

会话目录创建采用“先写临时目录，再原子移动到最终目录”的方式。主会话保存失败时保留错误，不删除旧数据；目录名一旦创建不随用户后续重命名改变，重命名只更新 `session.json.title`。

### 3. 旧会话迁移

- 读取先查新目录，再兼容读取旧的 `.storyfabric/sessions/<id>.json`。
- 工作区初始化时扫描旧文件，验证 JSON 和会话字段后复制到新目录；复制后读取校验通过，旧文件移动到 `.storyfabric/sessions/legacy/`，不直接丢弃。
- 新旧格式若出现同一 `id`，新目录优先，旧文件只作为迁移备份，不在列表中重复出现。
- 迁移任一文件失败时记录诊断并继续处理其他会话，不阻塞工作区打开。
- 工作区归档仍排除整个 `.storyfabric/sessions/`，避免把对话和临时运行数据带入项目压缩包。

### 4. 普通/编排模式切换

新增会话级创作模式控件，和目标模式分开：

- 普通模式：保存 `creative.mode=basic`、`orchestrationEnabled=false`、`subagentsEnabled=false`。
- 编排模式：保存现有编排配置，设置 `creative.mode=orchestration`、`orchestrationEnabled=true`。
- 目标模式仍由 `RunAgentRequest.mode=goal` 控制，不再被误认为普通/编排切换。
- 切换控件在全尺寸会话窗口和独立会话窗口都显示；运行期间禁用，下一次发送生效。
- 会话打开时从 `session.json` 恢复模式；新会话默认普通模式，完整智能体工作台可明确开启编排。
- 发送请求必须同时携带会话级 `creative` 快照和独立的 `mode`，核心分支只在 `mode !== goal` 时使用 `creative.orchestrationEnabled`。

### 5. 归档、删除和恢复

- 归档：只更新 `session.json.archived=true`，不移动目录、不删除 `tmp/`；归档列表仍能打开和取消归档。
- 删除：前端显示会话名称和目录范围确认；后端按会话 ID 解析受控目录，删除整个会话文件夹，包括 `session.json` 和 `tmp/`，不接受任意路径。
- 删除前如果会话正在运行，先拒绝删除并提示停止运行；删除活动会话后前端创建一个新的普通会话。
- 删除不进入项目资料回收站，但删除前提供会话导出入口；删除失败时保留目录并返回明确错误。
- 旧格式删除同时清理旧 JSON 或迁移备份中的同一会话，但不删除其他会话。

### 6. 统一写入版本

所有可写实体的读取回执统一返回 `writeRevision`，它必须由写入工具实际校验的规范化实体序列化结果计算。`sourceRevision` 只表示原始来源文件版本，用于溯源，不能再作为 `baseRevision` 的隐式替代。

- `get_chapter`、`get_outline_doc`、`get_setting` 等返回 `writeRevision`。
- `search_project` 的命中项返回 `sourceRevision` 和可写实体的 `writeRevision`；若命中只是片段，没有完整实体则明确标记不可直接写入。
- 工具提示和 schema 改为要求更新工具使用 `writeRevision`。
- 保存前和确认后应用前都重新读取当前实体，用同一规范化序列化函数比较；冲突返回结构化、可恢复错误，不伪装成审批失败。

### 7. 审批与编排恢复

- 待确认变更携带 `sessionId`、`runId`、`stageId` 和 `mutationKind`，确认请求必须按会话和变更 ID 定位，避免跨会话误确认。
- 严格审批进入等待前，将待确认变更持久化到 `session.json` 和编排运行记录；确认、拒绝、取消后清除等待状态并写入结果。
- 自动审批不发出等待事件，直接执行 `apply()`；应用失败仍生成 `change-result=failed` 和工具错误回执。
- 可重试的读取/版本冲突错误返回给当前阶段模型，允许先重新读取再提交；连续相同失败仍由工具循环保护停止。
- 阶段失败记录失败原因、最后一个工具回执、可恢复动作和当前阶段；后续阶段不再只显示“停住”，而是显示“失败/等待确认/可重试”。
- 编排器仍保留规划门禁：未完成计划、设定候选和写作 brief 时，不允许 `write` 阶段写正文。

### 8. 项目文档副本

在全部修复并通过测试后：

1. 读取 `E:\New项目\Novel\开局被抢课逼疯，我带全地府修仙\docs\修仙体系设计.md` 的最新内容和 revision。
2. 复制为 `docs/2026-09-19-修仙体系设计-编排适配副本.md`。
3. 在副本中添加“StoryFabric 现行协作规范”附录，明确普通模式、单智能体编排、多智能体编排、资料读取权限、写入审批和先计划后正文的边界。
4. 原文件保持字节和内容不变；副本保存必须经过当前会话的审批策略并记录来源 revision。

## 组件边界

| 组件 | 责任 |
|---|---|
| `CoreSessionStore` / `SessionStore` | 新旧会话路径、目录迁移、原子保存、归档和目录删除 |
| `ChatSession` / `SessionMeta` | 保存目录标识、会话模式、审批等待和列表元数据 |
| 主进程 IPC / HTTP RPC / Android API | 统一暴露目录会话、模式切换、归档和删除契约 |
| `chatStore` / `ChatPage` / `ChatSidebar` | 显示会话模式、切换会话级模式、归档删除反馈 |
| `CoreAgentService` | 按会话快照选择普通或编排，关联运行、审批和恢复状态 |
| `registry` / `projectCorpus` / retrieval | 统一 `writeRevision`，保证读取和写入基线一致 |
| `OrchestrationScheduler` / `runToolLoop` | 阶段错误分类、可重试失败、等待确认和恢复提示 |
| 文档迁移脚本或一次性任务 | 复制并更新指定项目文档副本，保留原文 |

## 验收标准

- 新会话首次发送后生成日期、描述和 ID 组成的文件夹，内部存在 `session.json` 与 `tmp/`。
- 旧 `.json` 会话可打开、可迁移、不会重复显示；迁移失败不会破坏原文件。
- 同一会话可以在普通和编排之间切换；普通模式的简单请求不会调用编排阶段。
- 归档/取消归档只改变列表归属；删除会话删除整个受控目录，不误删其他目录。
- 严格审批的待确认变更可确认、拒绝、取消并恢复运行；自动审批写入不等待确认。
- `get_*`、`search_project`、`save_*` 使用同一 `writeRevision`，指定项目中的章节保存回归测试不再出现读取后仍无故版本冲突。
- 编排资料读取失败会显示具体工具、阶段和可恢复动作；必要阶段失败不会伪装成普通完成。
- 规划门禁仍阻止未完成资料准备时写正文。
- `docs/修仙体系设计.md` 原文不变，生成一份带现行协作规范附录的副本。

## 不变性与安全

- 所有会话路径由 ID/slug 生成并经过相对路径校验，禁止绝对路径、`..` 和跨工作区访问。
- 删除只接受会话 ID，不接受前端传入物理路径。
- 会话临时文件不进入长期资料检索，不进入工作区归档。
- 用户原始项目文档不覆盖；副本写入失败时保留原文并显示错误。
- 任何未通过新格式验证的会话只进入迁移诊断，不直接删除。
