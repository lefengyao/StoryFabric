# StoryFabric 产品介绍站统一改版设计

日期：2026-09-13

## 背景

`StoryFabric-web` 是一组不依赖构建工具的静态产品介绍页，当前包含产品首页、写作台、故事世界、智能体和下载页。页面已经有暖纸张、深蓝墨色、衬线标题和珊瑚色强调的视觉基础，但部分文案和展示型 UI 与实际 StoryFabric 应用能力不完全一致，页面之间的导航、术语和界面密度也不统一。

实际产品是 AI 小说创作工作台：章节按卷组织，并区分草稿、正文和回收箱；大纲、角色、关系、设定、事件和便签构成可读的故事资料；智能体会按需读取章节与上下文，工具过程可见，涉及写入时需要用户确认。当前主要平台是 Windows Electron 桌面端，Web 端作为服务形态存在，移动端不在本次主宣传范围内。

## 目标

1. 让五个页面形成一个完整、连贯的产品叙事，用户能从首页自然进入各个能力演示。
2. 让展示 UI 对齐真实产品的信息架构、交互边界和术语，不暗示“全自动写作”或不存在的云端能力。
3. 保留现有静态站的原生 HTML、CSS、JavaScript 约束，不引入构建工具、后端或外部依赖。
4. 在桌面和移动视口下都保持可读、可操作和视觉层级稳定。

## 非目标

- 不改动内层 Electron 应用功能或数据结构。
- 不把静态演示页改造成真实后端产品。
- 不新增登录、注册、在线同步、真实下载服务或移动端发布承诺。
- 不为展示页引入真实的 AI 请求或外部字体资源。

## 推荐方向

采用“产品实况工作台”方向。页面以真实应用的界面切片为主视觉，品牌叙事只负责解释创作流程；各页都展示“资料如何组织、智能体如何读取、写入如何被确认”这条主线。这样比单纯功能卡片更能建立可信度，也比纯氛围化创作叙事更能表达实际产品。

## 页面设计

### 首页 `StoryFabric-web/index.html`

- 首屏明确定位为“把小说资料、章节结构和可控智能体放在同一张工作台上”。
- 主视觉使用工作台总览：左侧导航和卷章树、中间章节正文、右侧智能体上下文/动作状态；展示真实的章节标题、草稿与正文状态、资料来源和确认写回。
- 能力叙事按四段组织：章节写作、故事资料、连续性上下文、可控写回。
- 用真实边界替换夸张表述：智能体“按需读取”资料，“提出修改”并“等待确认”，不宣称自动完成长篇创作。
- 平台区以 Windows Electron 桌面端为主要 CTA；Web 端只作为服务形态补充说明。

### 写作台 `StoryFabric-web/workbench.html`

- 展示卷章结构和当前章节选择，明确章节有“草稿 / 正文 / 回收箱”三个状态。
- 中央区域保持干净的 Markdown/正文编辑感，加入自动保存、最近续读和 AI 续写入口等真实状态。
- 将原本泛化的侧栏按钮统一为产品术语：大纲、章节、角色、事件、设定、便签，并保持与首页和故事世界页一致的计数及图标样式。
- 所有按钮继续作为演示交互，不连接真实 API；交互结果通过页面内状态变化表达。

### 故事世界 `StoryFabric-web/world.html`

- 以资料库为核心，而不是独立的“角色展示页”。
- 展示人物卡片、关系图谱、事件脉络、设定和便签之间的关联，明确这些资料可以作为智能体的上下文来源。
- 关系图谱保持视觉焦点，但增加来源/状态标签，避免把演示数据误解成自动推断结果。
- 统一与写作台的导航词汇、计数样式和卡片边界。

### 智能体 `StoryFabric-web/agent.html`

- 保持“查资料，也会停下来”的核心叙事，重点展示对话、资料读取、工具过程和修改预览。
- 将工具时间线明确为“已读取的章节/资料”和“准备修改的目标”，并在写回前呈现确认状态。
- 修改预览使用 diff/前后对照片段，强调用户拥有最终写入权。
- 文案说明智能体会根据当前工作区读取相关资料，而不是无边界地读取全部内容。

### 下载 `StoryFabric-web/download.html`

- 与首页平台区保持相同的 Windows Electron 定位和版本口径。
- 将流程说明统一成“下载安装包 → 安装或解压 → 打开工作区”。
- 明确页面提供的是当前桌面端入口；Web 端和移动端说明只描述现状，不承诺未发布能力。

## 视觉系统

- 保留暖纸张背景、深蓝墨色、珊瑚强调色、金色标记和青绿色状态色，减少无语义的装饰色。
- 将重复的导航、按钮、标签、工作台面板、状态点、卡片和 footer 规则集中到 `assets/styles.css`。
- 展示 UI 使用细边框、低饱和背景和轻阴影，接近真实编辑器的工具感；营销标题继续使用现有中文衬线字体栈，正文和 UI 使用现有无衬线字体栈。
- 用小幅度进入动画、悬停和 tab 切换增强可读性，不加入会干扰阅读的持续运动。
- 页面中所有品牌/产品名称统一为“织章 StoryFabric”，导航标签统一为“产品 / 写作台 / 故事世界 / 智能体 / 下载”。

## 内容真实性规则

- 使用“辅助、读取、建议、预览、确认、写回”等可验证动词。
- 不使用“自动写完整本小说、无需管理上下文、云端实时同步、全平台可用”等未经产品支持的表述。
- 演示数字（章节数、人物数、关系数、模型用量）保留为演示数据，并在站点说明中明确这一点。
- 版本和平台描述以当前 Windows 桌面端为准；若没有实际下载地址，CTA 只跳转到现有下载页或展示安装流程。

## 技术与验证

- 只修改 `StoryFabric-web` 下的 HTML/CSS/内联脚本和必要的 README 文案。
- 复用现有页面脚本和 class 命名，优先做局部替换，避免破坏现有 tab、菜单、滚动和演示交互。
- 使用静态文件服务打开五个页面，检查导航链路、移动端折叠、tab/菜单交互、无明显控制台错误和页面溢出。
- 用全文检索检查旧产品定位、平台承诺和页面术语是否仍有互相矛盾的残留。
