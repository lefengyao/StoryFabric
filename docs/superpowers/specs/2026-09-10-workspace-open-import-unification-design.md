# 跨平台工作区打开与导入统一设计

## 背景

网页端无法调用服务器的资源管理器。当前欢迎页在网页端只展示服务器已登记的工作区列表，无法通过服务器路径打开已有项目，也没有在“打开工作区”入口内直接选择压缩包导入。桌面端、网页端和 Android 端的工作区选择体验也不统一。

## 目标

在所有平台的“打开工作区”入口中提供一致的两种明确操作：

1. **打开已有文件夹**：打开一个已经存在且通过校验的工作区目录，不复制、不新建目录。
2. **导入压缩包**：选择 `.storyfabric.zip`，解压到新的工作区目录，禁止覆盖同名目录，并在成功后自动打开。

支持平台：Electron 桌面本地、Electron 远程服务、浏览器网页端、Android 本地和 Android 远程服务。

## 非目标

- 不在网页端实现任意服务器目录浏览器。
- 不允许通过工作区路径读取服务器任意文件。
- 不改变现有工作区归档格式和核心实体数据结构。
- 不把“导入”误实现为覆盖已有目录或直接打开压缩包内部内容。

## 用户流程

### 统一弹窗

点击欢迎页“打开工作区”后打开“打开工作区”弹窗，保留现有工作区列表作为快捷入口，并增加两个模式：

#### 打开已有文件夹

- 显示现有工作区列表；点击列表项直接打开。
- 提供“项目路径”输入框和“打开路径”按钮。
- Electron 本地端提供“浏览文件夹”，选择结果填入路径输入框；点击“打开路径”后才真正打开。
- 网页端和远程服务端不提供服务器文件夹选择器，用户粘贴服务器路径后点击“打开路径”。
- Android 本地端允许输入应用内部工作区路径；已有应用内部工作区仍通过列表选择。Android 远程模式使用服务器路径规则。
- 打开成功后关闭弹窗并进入工作区；失败时保留输入内容并显示服务端/平台返回的校验错误。

#### 导入压缩包

- 提供文件选择控件，接受 `.storyfabric.zip` 和 `application/zip`。
- Electron 本地端：选择归档后选择目标父目录；服务端/Android 不要求用户选择服务器或应用私有目录。
- 网页端/远程服务端：浏览器选择本地压缩包，上传到服务端工作区根目录，由服务端创建新目录并自动打开。
- Android 本地端：浏览器/WebView 文件选择压缩包，导入到应用私有 `workspaces` 根目录并自动生成不冲突的目录名。
- 默认名称由归档文件名推导；允许用户在导入前修改显示名称（不作为任意路径）。
- 导入期间显示忙碌状态，完成后刷新列表；失败时清理临时目录并显示错误。

### 语义约束

- “打开”只调用已有目录校验和打开逻辑，不创建或移动文件。
- “导入”只调用归档导入逻辑，必须经过临时目录、归档安全校验和原子发布。
- 同名目标目录不得覆盖；平台可以使用明确的用户确认名称或安全的唯一后缀策略，但不能静默覆盖。

## 路径与安全边界

### 本地平台

- Electron 继续使用系统目录选择器和本地路径 API。
- 粘贴路径与系统选择器得到的路径走同一个 `validateWorkspace` 校验。
- Android 的路径仅允许应用私有工作区根目录下的相对工作区路径，不接受设备任意绝对路径。

### 服务器平台

- 服务端增加“按服务器路径打开”能力，但只允许配置的托管工作区根目录内的路径。
- 路径必须经过 `resolve`/相对路径边界检查，拒绝根目录本身、`..` 穿越、符号链接逃逸和根目录外路径。
- 目标目录必须存在、是目录，并包含合法的 `storyfabric.json`；不满足时返回可读错误。
- 已登记工作区优先按登记 ID 打开，返回给客户端的 `WorkspaceSummary.path` 仍使用不透明工作区 ID，避免把服务器真实路径传播到后续 API。
- 对未登记目录：若它在允许根目录内且校验合法，则以新的不透明 ID 登记，并在注册表记录受控的相对目录位置；不移动、不复制、不修改原目录。若登记失败，不改变原目录内容。
- 服务器的压缩包导入继续由 `WorkspaceRegistry.importArchive` 负责，固定在托管根目录下新建工作区并自动绑定当前会话。

### 注册表兼容

- 现有记录继续使用 `id` 作为目录名，升级后可选增加 `directory` 字段；缺省时回退到 `id`，保证旧注册表无需手工迁移。
- 新登记的外部目录只保存允许根目录下的相对路径，加载和每次打开时重新做边界校验；拒绝绝对路径、空路径、`..` 穿越和重复目录。
- 目录删除或损坏时只从可打开列表中跳过，不自动删除用户目录；注册表修复/清理仍属于后续维护能力。

## API 设计

### 渲染端平台 API

新增一个语义明确的方法，避免把远程工作区 ID 与服务器真实路径混用：

```ts
openWorkspaceByPath(path: string): Promise<WorkspaceSummary>
```

- Electron：调用现有本地 `openWorkspace` 能力。
- Android：调用应用私有路径校验和打开能力。
- HTTP：调用新的服务器路径打开端点。

现有 `openWorkspace(path)` 保留，继续用于列表项对应的现有工作区标识；导入方法保持 `importWorkspace(bytes, fileName, target?)`，但统一由工作区入口调用。

### HTTP 端点

新增：

```http
POST /api/workspaces/open-path
Content-Type: application/json

{"path":"/srv/storyfabric/workspaces/demo"}
```

返回标准 `WorkspaceSummary`。服务端将真实路径解析为托管工作区 ID 后写入当前认证会话。

现有接口保持：

- `GET /api/workspaces`：列出可打开的托管工作区。
- `POST /api/workspaces/:id/open`：按不透明 ID 打开列表项。
- `POST /api/workspaces/import`：上传压缩包，创建新托管工作区并打开。

## 代码组织

- `WelcomePage` 负责统一弹窗、模式切换、路径输入、文件选择和错误/忙碌状态。
- 复用 `workspaceStore.importArchive` 与平台 API，不在页面内实现解压逻辑。
- `StoryFabricApi`、preload/IPC、`HttpPlatformApi`、`AndroidPlatformApi` 和服务端 registry 增加对应的路径打开能力。
- 将“选择归档文件并读取为 Uint8Array”的逻辑抽成可复用的小工具或组件，避免欢迎页和应用布局重复实现不同规则。

## 测试与验收

### 单元/接口测试

- 服务端路径打开：合法托管路径成功；根目录、目录外路径、`..` 穿越、符号链接逃逸、普通文件和损坏工作区均失败。
- 未登记但合法目录可以登记并打开；登记失败时不修改原目录。
- HTTP 路径打开返回标准摘要，并将会话绑定到不透明 ID。
- HTTP 导入仍创建新工作区，坏归档清理临时目录，已有工作区不被覆盖。
- Android 路径限制和导入唯一命名行为覆盖测试。
- HTTP 客户端发送路径打开请求，并保留现有列表打开/导入测试。

### 手工验收矩阵

| 平台 | 打开列表 | 粘贴路径打开 | 浏览文件夹/文件 | 导入后新建目录 | 自动打开 |
| --- | --- | --- | --- | --- | --- |
| Electron 本地 | 是 | 是 | 文件夹 + 压缩包 | 是 | 是 |
| Electron 远程 | 是 | 服务器路径 | 压缩包 | 是 | 是 |
| 浏览器网页 | 是 | 服务器路径 | 压缩包 | 是 | 是 |
| Android 本地 | 是 | 应用内部路径 | 压缩包 | 是 | 是 |
| Android 远程 | 是 | 服务器路径 | 压缩包 | 是 | 是 |

验收时确认：打开不会创建目录；导入不会覆盖目录；网页端不需要访问服务器资源管理器；错误提示能指出路径或压缩包原因；导入失败不会留下临时目录。

## 决策记录

- 采用统一弹窗而非为各平台复制不同流程，以保证“打开”和“导入”的语义一致。
- 不实现任意服务器目录浏览器；服务器路径输入必须受允许根目录约束。
- 导入始终走归档校验和新目录发布流程，不将压缩包当作工作区目录直接打开。
