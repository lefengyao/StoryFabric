# 会话字号偏好与工作台标题层级设计

## 状态

- 已获用户确认，进入实施计划阶段。
- 目标版本：0.1.8 快照版后续 UI 优化。
- 本设计不改变编排运行逻辑、模型调用逻辑或审批策略。

## 背景

当前聊天页同时由 `AppLayout` 和 `ChatPage` 显示“智能体工作台”，造成同一页面出现两个相同标题。聊天区域的字体大小也没有独立设置，只能受全局字号或组件内固定字号影响。

用户已选择 A 方案：保留顶层应用标题，移除会话内容区顶部的重复标题。用户还确认会话字号应作用于整个会话区域，包括聊天消息、输入框、工具回执、编排信息和智能体活动信息。

## 目标

1. 顶层导航继续显示“智能体工作台”，作为当前页面身份。
2. `ChatPage` 内部不再重复显示“智能体工作台”，但保留图标、模式切换、会话统计和编排面板入口。
3. 在设置页增加独立的“会话窗口字号”偏好。
4. 会话字号只影响聊天相关区域，不影响全局界面、编辑器、设置页或其他业务页面。
5. 完成后重启应用、切换工作区和切换普通/编排模式时，设置仍然稳定生效。

## 非目标

- 不改变消息气泡密度的间距语义；字号和密度是两个独立设置。
- 不使用 CSS `zoom` 缩放整个工作台，避免改变按钮尺寸、布局宽度和点击区域。
- 不改变小窗口默认模式、编排阶段配置、模型选择、审批模式或会话文件结构。
- 不为每个会话保存单独字号；字号是应用级偏好。

## 设计

### 标题层级

- 保留 `AppLayout` 的路由标题 `智能体工作台`。
- 移除 `ChatPage` 顶部重复的文字标题。
- `ChatPage` 顶部保留工作台图标、普通/编排模式选择、会话统计，以及编排模式启用时的编排面板。
- 标题去重后，不应留下空白标题占位；窄屏下不能因此增加横向溢出。

### 会话字号设置

在设置页“外观 → 聊天”区域新增：

- 字段名：`会话窗口字号`
- 建议选项：`13px`、`14px`、`16px`、`18px`、`20px`
- 默认值：`14px`，保持当前默认观感
- 说明：只影响聊天消息、输入框、工具回执、编排信息和智能体活动信息，不影响编辑器或其他页面

设置写入现有应用级 `settings.json`，并通过现有 `SettingsPatch` IPC 流程持久化。旧版设置文件缺少此字段时自动回退到 `14px`，不能导致设置加载失败。

### 样式作用范围

- 在 `AppSettings` / `PublicAppSettings` 增加会话字号字段。
- 在设置服务默认值和规范化逻辑中提供安全回退与范围约束。
- 在 `settingsStore` 的外观应用流程中写入 `--chat-font-size` CSS 变量。
- 变量只由聊天页面和聊天侧栏的会话容器消费，不能直接改变 `body` 或编辑器字号。
- 聊天区域的正文、输入框、工具回执、编排结果、运行时间线和智能体活动信息应统一继承或使用该变量；已有的消息气泡密度继续负责间距和 padding。
- 小窗口和完整聊天页共用同一个变量，避免两个界面设置不一致。

## 验收标准

1. 页面中只出现一个作为页面身份的“智能体工作台”标题。
2. 在设置页选择任一会话字号后，聊天消息、输入框、工具回执、编排信息和智能体活动信息即时更新。
3. 刷新页面、重启应用、重新打开工作区后，字号保持用户上次选择。
4. 调整会话字号不会改变编辑器字号、全局导航字号或设置页字号。
5. 旧设置文件无 `chatFontSize` 时仍能正常启动并使用 14px。
6. 普通模式与编排模式之间切换时，字号不丢失，标题布局不产生重复或跳动。
7. 完整测试通过，至少覆盖设置默认/兼容、CSS 变量映射和标题渲染回归。

## 测试策略

- 主进程设置服务：测试默认值、旧设置规范化和非法字号回退。
- 渲染器样式辅助函数：测试合法值映射、越界值夹紧和默认值。
- 设置页：测试字段展示与更新 patch。
- 聊天页：测试标题只渲染一次，以及聊天根节点使用会话字号变量。
- 构建验证：运行项目现有完整测试和 Windows 打包流程。

## 风险与回滚

- 风险：聊天组件中存在少量固定字号 utility class，可能不会自动继承新变量。实施时需要对会话区域内的固定字号点做有限的样式收口，并用回归测试覆盖关键区域。
- 风险：旧设置文件类型不完整。规范化必须在设置服务边界完成，避免渲染器收到 `undefined` 后出现布局抖动。
- 回滚：若字号变量导致窄屏布局异常，可仅关闭新 CSS 变量消费并保留设置字段，不影响旧版设置文件读取和其他功能。
